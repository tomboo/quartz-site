Project Management App

Unified personal project and task management using an Areas → Projects → Tasks → Backlog hierarchy, inspired by Things 3 and the PARA method.

Purpose

The Project Management app provides structured organization for work and life responsibilities across four levels:

  • Areas - Ongoing life categories (Work, Health, Learning) that don’t have end dates
  • Projects - Goal-oriented containers with defined outcomes and optional deadlines
  • Tasks - Actionable work items that move projects forward
  • Backlog - Quick-capture system for ideas and reminders to prevent distraction

This creates a clear hierarchy: Life Areas contain Projects, which contain Tasks, fed by the Backlog capture system.

Quick Start

Create a Task

Use natural language during any session:

create task to design homepage mockup for Website Redesign project due Friday p1

Claude will:

  1. Generate a ULID for the task
  2. Create file: task-YYYYMMDD-NNN.md
  3. Link to the specified project
  4. Set due date and priority
  5. Confirm creation

Create a Project

create project Website Redesign in Work area deadline March 1

View Your Tasks

Open components/project-management/project-management-dashboard.md for:

  • Today’s tasks (scheduled or due today)
  • Active projects overview
  • Areas at a glance

Core Concepts

Areas

Areas are the major categories of your life that require continuous attention. Unlike projects, they don’t have end dates—they represent ongoing responsibilities.

Default Areas:

AreaIconPurpose
Work💼Professional responsibilities, career
Personal🏠Home, admin, life management
Health & Fitness💪Exercise, nutrition, wellness
Learning📚Education, skill development
Family & Friends👨‍👩‍👧‍👦Relationships, social connections
Finance💰Money, investments, budgeting
Creative🎨Art, writing, hobbies

Projects

Projects are goal-oriented work with a defined outcome. They optionally have deadlines and always belong to an Area.

Project characteristics:

  • Has a clear definition of “done” (outcome)
  • Contains multiple related tasks
  • May have a deadline
  • Belongs to one Area
  • Has a status: not-started, active, completed, on-hold, cancelled

Tasks

Tasks are the atomic unit of work—specific, actionable items you can complete.

Two key date fields (inspired by Things 3):

  • when - Flexible intention: when you PLAN to work on this
  • deadline - Fixed obligation: when this MUST be done

This separation lets you schedule tasks for specific days without creating false urgency.

When vs Deadline: Deep Dive

One of Things 3’s most powerful design decisions is the separation between when (plan) and deadline (obligation). Understanding this distinction is crucial for stress-free task management.

When (Flexible Intention)

  • Purpose: “I plan to work on this today”
  • Feeling: Low pressure, flexible
  • Psychology: Positive intention, not a commitment
  • Typical use: Daily planning, time blocking
  • Behavior: Can be rescheduled guilt-free
  • Visibility: Shows in Today view, helps focus your day

Deadline (Fixed Obligation)

  • Purpose: “This must be done by this date”
  • Feeling: High pressure, urgent as it approaches
  • Psychology: External commitment, real consequences
  • Typical use: Client deliverables, bills, appointments
  • Behavior: Rescheduling requires negotiation/consequences
  • Visibility: Shows urgency indicators as date approaches

Best Practices:

  1. Use deadlines sparingly - Only for true hard deadlines

    • ✅ Client project due Friday
    • ✅ Pay rent by 1st of month
    • ✅ File taxes by April 15
    • ❌ “Finish reading book” (no external pressure)
    • ❌ “Clean garage” (flexible goal)

  2. Use when liberally - For daily planning and intentions

    • ✅ Schedule “Write blog post” for Wednesday
    • ✅ Block Thursday morning for “Review quarterly goals”
    • ✅ Plan “Call mom” for weekend

  3. Combine both for buffer time

    • Task: Prepare presentation
    • when: Wednesday (work on it)
    • deadline: Friday (must be done)
    • Result: 2-day buffer if something goes wrong

  4. Inbox tasks have neither - Uncategorized, not scheduled

    • Captured ideas waiting to be organized
    • Will be scheduled during weekly review

Examples:

TaskwhendeadlineReasoning
Submit expense reportWedFriWork on Wednesday, due Friday (buffer)
Daily standup9am daily—Recurring intention, not a deadline
Client deliverable—Mar 15True deadline, plan work separately
Write blog postMon—Personal goal, flexible timing
Pay credit card—1stHard deadline, do anytime before

Common Patterns:

  • when only: Personal goals, flexible work
  • deadline only: Bills, appointments (do anytime before)
  • Both: Important deliverables with buffer time
  • Neither: Inbox tasks, someday/maybe items

Backlog

The Backlog is a quick-capture system for ideas, tasks, and reminders that prevents distraction from current work. It’s the entry point for the entire system—ideas flow from Backlog → Tasks → Projects.

Backlog characteristics:

  • Quick capture with natural language
  • Minimal friction (no ceremony, AI handles details)
  • Triage weekly during reviews
  • Promote to Tasks when ready to execute
  • Cancel ruthlessly if no longer relevant

Key properties:

  • status: open, completed, canceled, someday
  • priority: p0-p3 for triage
  • category: Life area classification
  • estimate: Time/effort estimation
  • context: Why/where this came up

Workflow:

  1. Capture - Create backlog item during any session
  2. Triage - Weekly review, update priorities
  3. Promote - Move to Tasks when committed to work
  4. Complete - Mark done or cancel if no longer needed

For detailed documentation, see the Backlog section below.

Views

The Project Management app provides multiple views optimized for different workflows, inspired by Things 3’s organization philosophy.

Task Views

Access via components/project-management/tasks-base.base:

1. Inbox

Purpose: Uncategorized tasks waiting to be organized

Shows:

  • All open tasks (status = open)
  • No when date
  • No deadline
  • No project assigned

Workflow:

  1. New tasks land here by default
  2. During daily/weekly review, organize them:
    • Assign to project or area
    • Set when or deadline if time-sensitive
    • Cancel if no longer relevant
  3. Goal: Keep inbox at zero

Best for: Quick capture, weekly review

2. Today

Purpose: What to work on today

Shows:

  • Tasks with when = today (planned for today)
  • Tasks with deadline = today (due today)
  • Overdue tasks (deadline < today)
  • Status = open

Sorted by: Priority, then deadline

Workflow:

  • Review each morning
  • Reschedule tasks that won’t get done (guilt-free!)
  • Focus on completing this list

Best for: Daily execution, morning planning

3. Upcoming

Purpose: Next 7 days preview

Shows:

  • Tasks with when in next 7 days
  • Tasks with deadline in next 7 days
  • Status = open

Sorted by: Deadline, then priority

Workflow:

  • Weekly planning sessions
  • Identify conflicts and capacity issues
  • Reschedule overcommitted days

Best for: Weekly planning, capacity management

4. Someday

Purpose: Tasks without specific timeframes

Shows:

  • No when date
  • No deadline
  • Has project or area assigned (organized, unlike Inbox)
  • Status = open

Grouped by: Project/Area

Workflow:

  • Passive backlog of organized but unscheduled work
  • Pull from here during weekly review
  • Schedule when ready to commit

Best for: Long-term project tasks, “when I have time” items

5. Anytime (By Project)

Purpose: All open tasks organized by project

Shows:

  • Status = open
  • Grouped by project

Sorted by: Priority within each project

Best for: Project-focused work sessions, understanding project scope

6. Anytime (By Area)

Purpose: All open tasks organized by life area

Shows:

  • Status = open
  • Grouped by area

Sorted by: Priority within each area

Best for: Area-focused reviews (e.g., “Health week”, “Work sprint”)

7. Logbook

Purpose: Completed and canceled task history

Shows:

  • Status = completed or canceled
  • Includes completed-at or canceled-at timestamps

Sorted by: Completion date (newest first)

Best for: Progress tracking, weekly review retrospectives, accountability

8. All Tasks

Purpose: Complete task database

Shows: Every task regardless of status

Columns: Title, Status, Priority, Project, When, Deadline

Best for: Searching, data analysis, troubleshooting

Recurring Tasks

The Project Management app supports recurring tasks through the repeat property, inspired by Things 3’s flexible recurrence model.

Property: repeat (String)

Pattern Types

1. Fixed Schedule (repeats on calendar intervals)

Perfect for tasks that happen on a regular schedule regardless of when you complete them:

2. After Completion (repeats N time after completing)

Perfect for maintenance tasks where timing starts after completion:

When to Use Each Type

Fixed Schedule:

  • Team meetings (every Monday)
  • Daily habits (meditation, exercise)
  • Bills and deadlines (1st of month)
  • Regular reviews (weekly, monthly)
  • Example: Weekly standup always happens Monday 9am, regardless of when you mark it complete

After Completion:

  • Home maintenance (change air filter every 3 months after changing)
  • Health tasks (dental checkup 6 months after last visit)
  • Flexible maintenance (water plants 3 days after last watering)
  • Example: Change air filter completed Jan 15 → next instance scheduled Apr 15

Complete Examples

Fixed Schedule: Team Standup

Completes Friday → next instance still Monday 9am

After Completion: Change Air Filter

Completes Jan 15 → next instance scheduled Apr 15

Weekdays: Review Emails

Repeats Monday-Friday only, skips weekends

Workflow

  1. Create recurring task with repeat property
  2. Complete the task (mark status = completed)
  3. System auto-creates next instance:
    • Fixed schedule: Increments from original date
    • After completion: Increments from completion date
  4. Original task preserved with completed-at timestamp in Logbook

Best Practices

Choose the right pattern:

  • Use fixed schedule for time-sensitive commitments
  • Use after-completion for flexible maintenance tasks
  • Use weekdays for work-only tasks
  • Use custom intervals for non-standard schedules

Keep titles consistent:

  • Same title helps track history in Logbook
  • Use tags to distinguish instances if needed

Date field guidance:

  • Use when for most recurring tasks (flexible)
  • Use deadline only for recurring obligations (bills, reports)
  • Combine both if task has fixed deadline but flexible work time

Don’t over-use:

  • Only create recurring tasks for true patterns
  • One-off tasks should not have repeat
  • Review recurring tasks quarterly - cancel outdated ones

Implementation Status

  • ✅ Basic patterns (daily, weekly, monthly, yearly)
  • 🚧 After-completion patterns (schema defined, implementation pending)
  • 🚧 Complex patterns (weekdays, every-N-days) (schema defined, implementation pending)

See standards/schemas/app-schemas.md#repeat for complete technical specification.

Workflows

Daily Planning

  1. Open Today view each morning
  2. Review scheduled and due tasks
  3. Reschedule tasks that won’t get done
  4. Add any new tasks that came up
  5. Work through Today list

Weekly Review

  1. Review all active projects
  2. Check for stalled projects (no recent task activity)
  3. Process completed tasks
  4. Schedule tasks for the upcoming week
  5. Review areas for balance

Creating from Backlog

Promote backlog items to tasks when ready to execute:

promote backlog-20251217-001 to task in Website Redesign project

This creates a task linked to the original backlog item.

Best Practices

Task Naming

Use action verbs:

  • ✅ “Design homepage mockup”
  • ✅ “Review budget spreadsheet”
  • ✅ “Call dentist to schedule appointment”
  • ❌ “Homepage” (not actionable)
  • ❌ “Budget stuff” (vague)

Schedule Strategically

Use when and deadline together for important work with buffer time:

  • deadline: External deadlines, commitments to others
  • when: When YOU plan to work on it

Example: A report due Friday might be scheduled (when) for Wednesday, giving buffer time.

See the When vs Deadline: Deep Dive section for comprehensive guidance.

Keep Areas Stable

Areas should be relatively stable life categories. If you’re creating/deleting areas frequently, they might be better as projects.

Project Outcomes

Always define what “done” looks like:

  • ✅ “Live website with new design and portfolio”
  • ❌ “Work on website” (never ends)

Limit Active Projects

Per PARA method guidance, keep 10-15 active projects maximum. More than that indicates:

  • Some projects should be on-hold
  • Some “projects” are actually areas
  • Scope creep

Troubleshooting

Task not showing in Today view

Check:

  • Is when or deadline set to today?
  • Is status set to open (not completed or canceled)?
  • Is the file in _database/database-core/tasks-table/?

Project has no tasks

Either:

  • Tasks exist but aren’t linked (check project property)
  • Project is newly created and needs tasks added

Area seems empty

  • Check if projects are linked to the area
  • Ensure projects have area property set correctly

Backlog App Details

Quick Capture Workflow

Create backlog items with natural language during any session:

create backlog item to research Obsidian plugin API
create p1 backlog item to fix critical bug
create backlog item for health-fitness to schedule checkup estimate 30m

What AI does automatically:

  1. Generates ULID for unique identification
  2. Creates file: _database/database-core/backlog-table/backlog-NNN.md
  3. Parses priority, category, estimate from natural language
  4. Sets defaults (priority: p2, status: open)
  5. Confirms creation

Backlog Properties

Required:

  • uid - ULID identifier
  • date - Creation date
  • user - Creator
  • title - Brief description

Standard:

  • status - open | completed | canceled | someday
  • priority - p0 (critical) | p1 (high) | p2 (medium) | p3 (low)
  • category - Life area (health-fitness, learning, work-projects, etc.)
  • tags - Categorization
  • created-at - Timestamps

Optional:

  • estimate - Time estimate (30m, 2h, 3d)
  • context - Why/where this came up
  • deadline - Due date if time-sensitive
  • related-to - Links to sessions/projects
  • github-issue - GitHub issue number if promoted

Triage Strategies

Weekly Review:

  1. Open backlog views in components/project-management/backlog-base.base
  2. Sort by priority and date
  3. Review open items
  4. Update priorities based on current goals
  5. Cancel items no longer relevant

Quick Wins: Filter for:

  • estimate: 30m or less
  • priority: p0, p1, or p2
  • status: open

Perfect for short productive breaks.

Category Focus:

  • Health week: category: health-fitness
  • Learning sprint: category: learning
  • Home maintenance: category: home-maintenance

Promoting to Tasks

When ready to commit to work on a backlog item:

promote backlog-001 to task in Website Redesign project

This creates a task linked to the backlog item, moving it from “someday” to “committed.”

Best Practices

Capture Immediately:

  • Don’t let ideas interrupt current work
  • Use natural language, no ceremony
  • AI handles all details

Add Context:

  • Include why/where idea came up
  • Link to related sessions
  • Future you will thank you

Be Ruthless:

  • Cancel items that no longer matter
  • Don’t let backlog become overwhelming
  • Delete completed items if no history value

Review Regularly:

  • Weekly triage keeps backlog healthy
  • Update priorities as life changes
  • Celebrate completed items
