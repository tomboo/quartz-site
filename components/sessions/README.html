Sessions App

Track work sessions with Claude Code, capture progress, and maintain comprehensive session history.

Purpose

The Sessions app provides structured workflows for beginning, working through, and concluding collaborative sessions with Claude Code. It ensures:

  • Continuity: Each session starts with context from previous work
  • Documentation: Comprehensive notes capture what was accomplished
  • Git Integration: Automated, well-formatted commits at checkpoints and session end
  • Focus: Clear goals and accountability for each session
  • Health Monitoring: AI validates schema compliance and framework health

Quick Start

Start a Session

/session-start

This will:

  1. Sync with remote (git pull)
  2. Review recent commits and last session notes
  3. Check recent vault modifications
  4. Display context usage
  5. Ask what you want to focus on

During a Session

Work naturally with Claude Code. Every 15-30 minutes:

/session-commit

This creates checkpoint commits (local only, no push).

End a Session

/session-end

This will:

  1. Create comprehensive session note
  2. Auto-generate commit message
  3. Run health checks
  4. Display context usage
  5. Ask for commit confirmation
  6. Optionally push to remote

File Structure

Location

All session files are stored in planning/sessions/.

Naming Convention

Pattern: session-YYYYMMDD-NNN.md

Examples:

  • session-20251213-001.md - First session on Dec 13, 2025
  • session-20251213-002.md - Second session on same day
  • session-20251214-001.md - First session on Dec 14, 2025

Components:

  • session- prefix
  • Date: YYYYMMDD (compact, sortable)
  • Session number: NNN (zero-padded, 001-999)

Property Details

uid

  • Type: String (ULID)
  • Auto-generated: Yes (by AI)
  • Format: 26-character Base32 encoded
  • Example: 01KAGWC2WNMNDGH2PP6NYZY8BY
  • Purpose: Unique identifier for cross-referencing

date

  • Type: Date
  • Format: YYYY-MM-DD
  • Example: 2025-12-13
  • Purpose: Primary date of session

session

  • Type: Number
  • Format: Positive integer (1, 2, 3…)
  • Purpose: Distinguish multiple sessions on same day
  • Usage: Combined with date for filename

user

  • Type: String
  • Default: tomboo
  • Purpose: Session owner/creator

focus

  • Type: List of Strings
  • Format: kebab-case values
  • Required: At least one focus area
  • Common values:
    • writing - Content creation, documentation
    • organization - Vault structure, file management
    • projects - Specific project work
    • research - Information gathering
    • review - Editing, refactoring
    • planning - Strategic planning
    • learning - Skill development
    • health-fitness - Exercise, nutrition tracking

duration-estimate

  • Type: String
  • Format: ~Xh, ~Xm, or ~XhYm
  • Examples: ~2h, ~45m, ~1h30m
  • Purpose: Planned session length
  • Tilde (~): Indicates estimate

actual-duration

  • Type: String
  • Format: Xh, Xm, or XhYm (no tilde)
  • Example: 2h15m
  • Purpose: Track actual time spent
  • Usage: Compare estimates vs. actuals

Session Note Structure

Created automatically by /session-end:

Slash Commands

/session-start

Purpose: Begin a new working session

What it does:

  1. Checks git status
    • Stops if uncommitted tracked changes exist
    • Automatically runs git pull if clean
  2. Reviews recent commits (last 5)
  3. Checks git user identity
  4. Reads most recent session note
  5. Lists recently modified files
  6. Displays context usage
  7. Asks for session focus

Output includes:

  • Recent commits summary
  • Last session summary
  • Recent vault modifications
  • Context status
  • Prompt for focus area

When to use: At the start of every work session

/session-commit

Purpose: Create checkpoint commits during active work

What it does:

  1. Analyzes changed files
  2. Categorizes changes (content, organization, config)
  3. Generates descriptive commit message
  4. Creates LOCAL commit (no push)
  5. Displays commit summary

When to use: Every 15-30 minutes during active sessions

Note: Commits are local only. Use /session-end to optionally push.

/session-end

Purpose: Conclude a working session with comprehensive tracking

What it does:

  1. Creates detailed session note in planning/sessions/
  2. Auto-generates commit message from session work
  3. Runs health checks on modified files
  4. Displays context usage
  5. Asks for commit confirmation
  6. Offers push to remote (optional)

Output includes:

  • Session note with full structure
  • Health check results
  • Context status
  • Commit preview

When to use: At the end of every work session

Health Monitoring

AI validates at session boundaries:

Schema Compliance

  • All session files have required properties
  • Properties follow correct formats
  • UIDs are valid ULIDs
  • Dates are valid ISO 8601

Naming Conventions

  • Files follow session-YYYYMMDD-NNN.md pattern
  • Properties use kebab-case
  • Values use kebab-case

Data Integrity

  • UIDs are unique across vault
  • No duplicate session numbers for same date
  • All references resolve correctly

Auto-Fix Capability

With user confirmation, AI can:

  • Add missing properties
  • Fix format violations
  • Generate missing UIDs
  • Rename files to conventions

Context Management

Display Format

All session commands show:

Context: 39K/200K (19% used, 161K remaining) ✓

Warning Levels

  • GREEN (0-50%): ✓ Healthy
  • YELLOW (51-75%): ⚠ Monitor
  • RED (76-90%): 🔴 Consider snapshot
  • CRITICAL (91-100%): 🚨 Consolidation recommended

Manual Consolidation

Use /session-snapshot when:

  • Context approaching 75%+
  • Before complex multi-file refactoring
  • When context feels “bloated”
  • At end of major work phases

Migration from Old Format

If you have existing session files in old format:

Old format:

planning/sessions/2025-12-13-session-1-framework-planning.md

New format:

planning/sessions/session-20251213-001.md

Migration adds:

  • ULID in frontmatter
  • Kebab-case properties
  • Consistent filename pattern
  • Timestamps (created-at)

See migration plan in Phase 2 implementation.

Best Practices

Consistent Usage

  • Always start with /session-start
  • Use /session-commit every 15-30 minutes
  • Always end with /session-end

Focus Definition

  • Be specific with focus areas
  • Use 1-3 focus values (don’t over-categorize)
  • Combine related work under single focus

Duration Estimates

  • Be realistic with estimates
  • Track actuals to improve future estimates
  • Consider breaks in longer sessions

Session Notes

  • Let AI generate the structure
  • Add your own notes in the Notes section
  • Use Next Steps for clear follow-up

Git Hygiene

  • Checkpoint commits keep work safe
  • Session-end commits are comprehensive
  • Push to remote at logical breakpoints

Troubleshooting

Session number not incrementing

  • Check existing session files for today’s date
  • Verify numbering is sequential (001, 002, 003)
  • AI should auto-detect and use next number

Health checks failing

  • Review error messages from /session-end
  • Use auto-fix if offered
  • Manually fix in Obsidian if needed

Context usage high

  • Use /session-snapshot to consolidate
  • Consider ending session and starting fresh
  • Review what’s consuming context

Git conflicts on pull

  • /session-start will warn if uncommitted changes
  • Commit or stash changes before starting session
  • Resolve conflicts manually if needed
