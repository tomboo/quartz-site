CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Overview

This is an Obsidian personal vault for knowledge management and note-taking. The vault is git-tracked with session-based workflows for collaborative work with Claude Code.

Owner: Tom (tomboo / tom.booster@gmail.com)

Research & Documentation Guidelines

When researching features, syntax, or capabilities of tools and technologies used in this vault, always check official documentation first before performing general web searches.

Official Documentation Sources

Obsidian:

  • Primary: https://help.obsidian.md/
  • Use for: Core features, plugins, syntax, settings, API documentation
  • Check here first for any Obsidian-related questions

Bases Plugin:

  • Official help: https://help.obsidian.md/bases/syntax
  • Forum: https://forum.obsidian.md/ (search “Bases”)
  • Use for: Filter syntax, view configuration, property usage

Research Workflow

  1. Check official docs first - Most accurate, up-to-date information
  2. Search community forums - Real-world examples and solutions
  3. General web search - Only if official sources don’t have the answer
  4. Verify with testing - Test findings in actual vault when possible

Why Official Documentation First?

  • Accuracy: Official docs reflect current version capabilities
  • Completeness: Covers all features, not just common use cases
  • Authority: Direct from developers who built the tool
  • Efficiency: Faster than sifting through search results

Example: Questions about Bases filter syntax should check https://help.obsidian.md/bases/syntax before doing web searches, as third-party sources may be outdated or incomplete.

Session Workflow Commands

Six slash commands manage structured work sessions and framework health:

Core Session Commands

/session-start

Begin a new working session. This command:

  • Syncs with remote (git pull if clean)
  • Reviews recent commits and last session notes
  • Verifies git user identity
  • Checks recent vault modifications
  • Displays context usage status
  • Prompts for session focus (Writing, Organization, Projects, Research, Review)

CRITICAL: Stops if uncommitted tracked file changes exist - user must commit or stash first.

/session-commit

Create periodic checkpoint commits during active work:

  • Analyzes and categorizes changed files
  • Generates descriptive commit messages
  • Creates LOCAL commits only (no push)
  • Use every 15-30 minutes during active sessions
  • Safety checks for sensitive data

Note: Renamed from /auto-commit in framework v1.0.

/session-end

Conclude a working session with comprehensive tracking:

  • Displays context usage status
  • Runs health checks on modified files
  • Creates detailed session note in _database/database-core/sessions-table/ with format session-YYYYMMDD-NNN.md
  • Generates ULID for session
  • Auto-generates commit message from session work
  • Asks for confirmation before committing
  • Offers push to remote (no automatic push)

Session notes include: summary, content created, organization work, files modified, next steps.

Context Management Commands

/context-status

Display current context usage and health:

  • Shows context usage percentage and remaining capacity
  • Color-coded health indicators (GREEN/YELLOW/RED/CRITICAL)
  • Breakdown by category (transcript, file reads, tool outputs)
  • Recommendations based on usage level

Use when: Monitoring during long sessions, before complex operations, when concerned about context.

/session-snapshot

Manually consolidate context with full transparency:

  • Display before/after context metrics
  • Preview what will be summarized vs. preserved
  • User approval required before consolidation
  • Typical reduction: 50-70% of context usage

Use when: Context reaches 75%+, before major refactoring, after extensive exploration.

Health Monitoring Commands

/health-check

Run comprehensive vault health validation:

  • Schema compliance (properties, formats, types)
  • Naming conventions (files, properties, values)
  • Data integrity (unique UIDs, valid references)
  • Framework standards adherence
  • Auto-fix capabilities with user approval

Underlying command: python3 -m _framework.cli.main doctor

Use when: Weekly maintenance, after migrations, before critical work, troubleshooting.

Obsidian Configuration

Editor Mode: Preview mode (Live Preview disabled) Links: Wiki-link format [[note]], relative paths Attachments: Stored in vault root (no dedicated folder) Daily Notes: Auto-created in _database/database-core/daily-notes-table/ with format YYYY-MM-DD Theme: Moonstone, 16px base font

Core Plugins Enabled: Daily notes, templates, word count, canvas, properties

Git Workflow

Branch: main (no separate development branches)

What’s Tracked:

  • All markdown content (notes, projects)
  • Templates
  • Session notes in _database/database-core/sessions-table/
  • .obsidian/ config (except workspace, cache, and most plugin data)
  • .claude/commands/ slash commands

What’s Ignored:

  • .obsidian/workspace*.json (local view state)
  • .obsidian/cache/ (rebuild on open)
  • Most .obsidian/plugins/*/data.json
  • OS files (.DS_Store, Thumbs.db)

Commit Philosophy:

  • Session-based commits through /session-end command
  • Periodic checkpoint commits via /session-commit during active work
  • Descriptive messages with file categorization
  • No automatic pushes - user confirms before pushing to remote

Working with This Vault

Starting Work:

  1. Run /session-start to sync and review recent activity
  2. Confirm focus area when prompted
  3. Begin writing, organizing, or researching

During Work: 4. Use /session-commit every 15-30 minutes for checkpoints 5. Use /context-status to monitor context usage during long sessions 6. Use /session-snapshot if context reaches 75%+ to consolidate 7. Work in Obsidian or edit markdown files directly

Ending Work: 9. Run /session-end to create session notes 10. Review generated commit message and health check results 11. Confirm commit when ready 12. Optionally push to remote

Maintenance:

  • Run /health-check weekly or after bulk operations
  • Review and fix any schema or naming issues
  • Keep vault in healthy state

Template Usage:

  • Daily notes: Auto-created with Cmd+D using _framework/templates/daily-note-template.md
  • Projects: Use _framework/templates/project-template.md for new projects
  • Tasks: Use _framework/templates/task-template.md for task notes

Common Issues

Session tracking:

  • Session notes go in _database/database-core/sessions-table/
  • Filename is ULID: 01KF14VPEC8E5W5JER92ECNY0M.md
  • Always check for existing session notes today before creating new one

Creating new files (v3 pattern):

  • Generate ULID for filename: 01KF14VPEC8E5W5JER92ECNY0M.md
  • Store title in frontmatter title: property
  • Use wikilinks with ULID: [[01KF14VPEC8E5W5JER92ECNY0M]]
  • Optionally add alias: [[01KF14VPEC8E5W5JER92ECNY0M|Display Title]]

Git conflicts:

  • /session-start will stop if uncommitted tracked changes exist
  • User must manually commit or stash before starting new session
  • This prevents accidental overwrites from git pull

Personal Operating System Framework

This vault implements a Personal Operating System framework (v3.0) for managing knowledge, tasks, and life priorities. The framework uses native Obsidian features enhanced with AI-integrated workflows.

Framework v3 Features

ULID-Based Filenames:

  • All files use ULID as filename: 01KF14VPEC8E5W5JER92ECNY0M.md
  • Title stored in frontmatter title: property
  • Enables stable links even when titles change

SQLite Index:

  • Derived index at .cache/index.db (gitignored, rebuildable)
  • Fast queries across 400+ files
  • Tables: files, tags, links, errors

Lexi CLI:

Split Schemas:

  • Per-type JSON schemas in _framework/schemas/
  • Core schema with shared definitions
  • Type-specific schemas use $ref composition

  • /context-status for on-demand monitoring
  • /session-snapshot for manual consolidation
  • Color-coded warnings (GREEN/YELLOW/RED/CRITICAL)

Framework Philosophy

This is a Personal Operating System designed to:

  • Maintain focus on life priorities
  • Prevent distraction and ensure balance
  • Track progress with data-driven insights
  • Provide AI-assisted accountability and monitoring

Core Principles:

  • Simplicity and elegance
  • Incremental development
  • AI as core component (proactive, not reactive)
  • Database-like consistency (ULIDs, schemas)
  • Single-user optimization (not for sharing)

Using the Backlog App

The Backlog app provides frictionless capture of ideas, tasks, and reminders during any session.

Creating items (natural language):

create backlog item to research Obsidian plugin API tomorrow @learning #technical high 2h
create backlog item to fix critical bug 0 30m @technical #urgent
create backlog item to schedule dentist appointment next week @health-fitness 1h

Natural Language Parsing: The framework includes an NLP parser that extracts structured data from conversational input:

  • Dates: tomorrow, next week, next Monday, Jan 15, 2025-01-15
  • Priorities: critical/0, high/1, medium/2, low/3
  • Estimates: 30m→PT30M, 2h→P2H, 1.5h→P1H30M (auto-converts to ISO 8601)
  • Categories: @learning, @health-fitness, @technical (use @ prefix)
  • Tags: urgent, bug, feature (use # prefix)
  • Title: Remaining text after extracting metadata

What AI does automatically:

  • Generates ULID for unique identification
  • Creates file: _database/database-core/backlog-table/{ULID}.md (ULID as filename)
  • Parses natural language using NLP parser (_framework/lib/nlp_parser.py)
  • Extracts and converts metadata (dates, priorities, estimates)
  • Renders template with structured data (_framework/lib/template_engine.py)
  • Sets defaults: status=draft, priority=2 if not specified

Item properties:

  • Required: type, user, title, created-at
  • Standard: status, priority, category, tags
  • Optional: estimate, context, related-to, github-issue, deadline

Status values (v3 standard):

  • draft - Not started, planning stage
  • active - Currently being worked on
  • completed - Finished successfully
  • on-hold - Paused, waiting on something
  • archived - No longer relevant, kept for reference

Viewing backlog:

  • Open components/project-management/views/backlog-base.base in Obsidian for filtered views
  • Views: All Items, Open Items, By Priority, Quick Wins

Common categories:

  • health-fitness, learning, family-friends, travel-culture
  • work-projects, personal-development, home-maintenance, creative, technical

Workflow:

  1. During session, ideas pop up → capture immediately with natural language
  2. Weekly review → triage by priority, update status, cancel irrelevant
  3. Work sessions → pull high-priority items, mark in-progress
  4. Completion → mark completed or delete file

GitHub promotion (optional):

  • Promote backlog items to GitHub Issues when they become projects
  • Set github-issue property to link them
  • Use for collaboration, bug tracking, or multi-session features

Task Comment Format

Tasks and backlog items use a standardized comment log at the bottom of the file for tracking updates, completion notes, and cancellation reasons.

Format:

Common comment titles:

  • Completed - Summary of what was done
  • Canceled - Reason for cancellation
  • Update - Progress notes or status changes
  • Blocked - What’s blocking progress
  • Decision - Important decisions made

Example:

Guidelines:

  • Place at very end of file, after main content
  • Use --- horizontal rule to separate from content
  • Chronological order (newest at bottom)
  • Keep comments concise but informative
