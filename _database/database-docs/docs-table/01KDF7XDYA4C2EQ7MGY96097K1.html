Apps Registry

Central registry of all apps in the Personal Operating System framework.

Overview

Apps are the organizational units of the framework. Each app:

  • Has a specific purpose and scope
  • Follows the database-component separation pattern
  • Uses shared property schemas
  • Integrates with session workflows

App Development Pattern

Required Components

Every app must have:

  1. README.md - Usage documentation
  2. Database table - Data storage location
  3. Property schema - Defined in _database/database-*/schema.json
  4. Bases view - Primary view file

Optional Components

Apps may include:

  • Dashboard pages
  • Multiple views
  • Slash commands
  • Templates
  • PRD (for complex apps)

Directory Structure

components/{app-name}/
├── README.md           # Required: Usage docs
├── {app}-base.base     # Required: Primary view
├── {app}-home.md       # Optional: Dashboard
├── manifest.json       # Optional: Dependencies
└── PRD.md              # Optional: Requirements

_database/database-{db-name}/
├── schema.json         # Required: Schema definition
└── {table}-table/      # Required: Data files
    └── {item}-NNN.md

Integration Points

Cross-App References

Apps can reference each other:

Shared Properties

All apps use common properties from schema:

  • uid - ULID identifier
  • date - Creation/relevant date
  • user - Owner
  • type - Entity type
  • created-at - Timestamp

Session Integration

All apps integrate with session workflow:

  • Items created during sessions
  • Session notes reference app items
  • Health checks validate all apps

Adding New Apps

Process

  1. Design - Create PRD if complex
  2. Schema - Define properties in schema.json
  3. Database - Create table directory
  4. Component - Create component directory with README and view
  5. Register - Add to this registry
  6. Document - Update CLAUDE.md if needed

Naming Convention

  • App names: singular, kebab-case (project-management, subscriptions)
  • Table names: plural, kebab-case (tasks-table, subscriptions-table)
  • File names: singular prefix with numbering (task-001.md, subscription-001.md)
