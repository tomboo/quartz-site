Framework Changes: Dec 24-25, 2025

Purpose: Checklist of framework changes from vault-personal-tom to evaluate for porting to lexi-you-da-hoe.

Sessions Analyzed: 13 sessions (20251224-001 through 20251225-005)

1. Schema Changes (Things 3 Alignment)

Status Value Simplification

  • Tasks: not-started/in-progress → open, cancelled → canceled
  • Projects: active/planning → open, cancelled → canceled
  • Backlog: Same pattern as Tasks
  • Areas: Remove status property entirely (areas are perpetually active)

Completion Tracking

  • Add completed-at property (auto-set when status → completed)
  • Add canceled-at property (auto-set when status → canceled)
  • Add to: Tasks, Projects, Backlog

Property Renaming (Tasks)

  • scheduled-date → when (intention: “I plan to work on this”)
  • due-date → deadline (obligation: “This must be done by”)

Property Removal

  • Remove date from Tasks (redundant with created-at)
  • Remove context from Tasks (low value)
  • Remove actual-duration from Tasks (rarely used)
  • Remove modified-at from ALL files (use file.mtime instead)
  • Remove status from Areas (perpetually active)

Property Additions

  • Add repeat to Tasks (daily, weekly, monthly, yearly, after-completion)
  • Add checklist to Tasks (subtask items)
  • Add project-type to Projects (finite | ongoing)

Property Order Standard

uid, user, type, title, status, priority, description, when, deadline,
repeat, estimate, project, area, checklist, tags, created-at

2. File Naming Convention

Sequential Naming Migration

  • Tasks: task-YYYYMMDD-###.md → task-###.md
  • Backlog: backlog-YYYYMMDD-###.md → backlog-###.md
  • Subscriptions: subscription-YYYYMMDD-###.md → subscription-###.md
  • Sessions: Keep session-YYYYMMDD-###.md (date is semantically important)

Benefits:

  • Shorter filenames (9 chars saved per file)
  • Easier references: “task 7” vs “task-20251217-007”
  • Cleaner wikilinks: [[01KCPDVSFB19AJ4EHZYJAT9H78]] vs [[task-20251217-005]]

Migration Script: scripts/migrate-to-sequential-naming.py

3. App Structure Changes

App Consolidation

  • Merge apps/tasks/ into apps/project-management/
  • Merge apps/backlog/ into apps/project-management/
  • Create unified umbrella app with sub-views

App Flattening (Simple Apps)

  • Remove views/ subdirectory (files go directly in app folder)
  • Remove dashboards/ subdirectory
  • Keep nested structure only for complex apps (project-management)

Notes App

  • Create Notes app for casual note capture
  • Status workflow: draft → active → archived
  • Replace inbox/ folder with status: draft workflow

Backend Structure

  • Move daily-notes/ → _database/database-core/daily-notes-table/
  • Create _database/database-core/notes-table/
  • Ensure all data tables are in _database/database-core/*-table/ format

4. Bases View Improvements

Syntax Fixes (Critical)

  • Use filters: not filter: (plural is correct)
  • Use today() function, not date(now)
  • Remove formulas: sections (not yet supported)
  • Remove summaries: sections (not yet supported)
  • Add file.name as first column in all views (enables clickable rows)

Things 3 Views (Tasks)

  • Inbox: Uncategorized tasks (no project)
  • Today: when == today() OR deadline == today() OR status == 'in-progress'
  • Upcoming: Next 7 days, grouped by when
  • Someday: Organized but unscheduled
  • Anytime (By Project): Grouped by project
  • Anytime (By Area): Grouped by area
  • Logbook: Completed tasks, sorted by completed-at DESC
  • All Tasks: Unfiltered master view

Dashboard Views

  • Sessions dashboard (last 5 sessions)
  • Tasks dashboard (high-priority, sorted by priority)
  • Backlog dashboard (p0/p1 items only)

Key Architectural Decisions

  1. Things 3 Philosophy: Simple status model (open/completed/canceled), when vs deadline semantics
  2. Status-Based Workflow: Use status properties instead of folder-based organization (e.g., status: draft vs inbox/ folder)
  3. Flat App Structure: Simple apps don’t need views/ and dashboards/ subdirectories
  4. Sequential Naming: Stable IDs for long-lived content, date-based only for sessions
  5. Official Docs First: Always check official documentation before web searches
  6. Wiki-Links Standard: Use wiki-links for all internal references

Detailed Recommendations for lexi-you-da-hoe

MUST APPLY (High Impact, Low Risk)

1. Remove modified-at Property

Effort: Low (script-based) Impact: High (schema simplification) Rationale: file.mtime is automatic and maintenance-free. Lexi has 200+ files with modified-at that requires manual updates.

2. Bases Syntax Audit & Fix

Effort: Low Impact: Critical (views may not work correctly) Rationale: vault-personal-tom discovered filters: (not filter:), today() (not date(now)), and that formulas: aren’t supported.

Check in lexi:

  • All .base files use filters: (plural)
  • Date filtering uses today() function
  • No unsupported formulas: sections
  • All views have file.name as first column

3. Task Comment Format

Effort: Low Impact: Medium (consistency) Rationale: Standardized format for tracking task completion notes.

SHOULD APPLY (Medium Impact)

4. Task Status: Boolean → String

Effort: Medium (migration script needed) Impact: High (enables Things 3 views) Rationale: Boolean status (true/false) doesn’t support intermediate states or canceled items.

Current lexi:

Proposed:

Migration:

  • status: true → status: completed
  • status: false → status: open

5. Add when Property

Effort: Medium Impact: High (Things 3 semantics) Rationale: Separates “when I intend to work” from “when it’s due”.

Current lexi: Only due-date Proposed: when (intention) + deadline (obligation)

Migration:

  • Rename due-date → deadline
  • Add when as optional property
  • Most lexi tasks don’t have due-date anyway (9/19 are null)

6. Completion Tracking

Effort: Low Impact: Medium (better history) Rationale: Know when tasks were completed for analytics.

Add to tasks:

  • completed-at - Auto-set when status → completed
  • canceled-at - Auto-set when status → canceled

CONSIDER APPLYING (Lower Priority)

7. Remove inbox/ Folder

Effort: Medium Impact: Low (structural cleanup) Rationale: Status-based workflow (status: draft) is cleaner than folder-based.

Current lexi: 17 files in inbox/ Migration: Move to appropriate locations, use status properties

8. App Flattening

Effort: Low Impact: Low (simplification) Rationale: Simple apps don’t need views/ subdirectories.

Affected apps in lexi:

  • apps/beats/ (already flat)
  • apps/characters/
  • apps/locations/
  • apps/library/
  • apps/manuscript/
  • apps/sessions/
  • apps/tasks/

9. Priority Alignment

Effort: Low Impact: Low (convention change) Current: high, medium, low Proposed: p0, p1, p2, p3

Recommendation: Keep lexi’s current format. It’s clear and works for a writing vault with fewer tasks.

DO NOT APPLY

App Consolidation (tasks+backlog → PM)

Reason: Lexi doesn’t have a backlog app. Task structure is simpler and appropriate for writing context.

Notes App

Reason: Lexi has drafts/ for WIP content and a different organizational model focused on writing artifacts (beats, characters, locations).

Things 3 Views (Full Set)

Reason: Lexi’s task model is simpler. 19 tasks don’t need 8 views. Keep existing 5-view structure (Active, By Priority, By Status, Completed, All Tasks).
