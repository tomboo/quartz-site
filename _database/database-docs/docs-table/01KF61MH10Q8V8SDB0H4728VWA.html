Web Publishing Comparison and Recommendation

Comprehensive evaluation of options for publishing this Obsidian vault to the web.

Overview

This document evaluates web publishing platforms for the Personal Operating System vault, considering its unique characteristics: ULID-based filenames, Bases usage, framework code to exclude, and the goal of publishing most content publicly.

Decision Date: 2026-01-17 Recommendation: Quartz

Detailed Analysis

Obsidian Publish

Overview: Official first-party publishing service from Obsidian.

Pros:

  • Zero configuration required
  • Native Obsidian integration
  • Automatic updates when vault changes
  • Custom domain support
  • Password protection available
  • Graph view and hover previews

Cons:

  • $100/year ongoing cost
  • No Bases support (confirmed “not yet” by moderators)
  • Limited customization options
  • No local preview capability
  • Vendor lock-in

ULID Handling:

The permalink: frontmatter field overrides the filename-based URL.

Best For: Users who want zero-friction setup and don’t mind the cost.

Documentation: https://help.obsidian.md/publish

Quartz

Overview: Free, open-source static site generator designed for Obsidian vaults.

Pros:

  • Completely free
  • Highly customizable (full template control)
  • Excellent for bulk publishing
  • Local development server for preview
  • Strong community and active development
  • ignorePatterns for excluding private content
  • Quartz Syncer plugin compiles Dataview to static
  • Graph view, backlinks, full-text search included

Cons:

  • Requires Node.js and Git knowledge
  • More complex initial setup
  • No Bases support
  • Filters only work on markdown (non-md files need manual exclusion)

ULID Handling:

If no permalink:, Quartz uses title: property. Falls back to filename if neither exists.

Exclusion Configuration:

Best For: Technical users publishing most of their vault who want full control.

Documentation: https://quartz.jzhao.xyz/

Digital Garden

Overview: Free Obsidian plugin for selective note publishing via GitHub and Vercel.

Pros:

  • Free hosting
  • Native Dataview support (best of all options)
  • Fine-grained publish control via frontmatter
  • dg-permalink: for custom URLs
  • Supports graph view, backlinks, search

Cons:

  • Requires marking each note with dg-publish: true
  • Poor fit for “publish most” use case (must mark hundreds of files)
  • No local preview
  • No Bases support
  • Moderate setup complexity

ULID Handling:

Best For: Selective publishing (cherry-pick specific notes).

Documentation: https://dg-docs.ole.dev/

Flowershow

Overview: Hosted platform evolved from a Next.js template, now offering managed publishing.

Pros:

  • Easy setup with managed hosting
  • Good blogging features (author profiles, comments)
  • Cheaper than Obsidian Publish ($50/year premium)
  • Custom domain support

Cons:

  • No Dataview support
  • No graph view
  • No Bases support
  • Full-text search only on premium
  • Less documented permalink handling
  • Less mature than other options

Best For: Blog-style publishing with minimal technical overhead.

Documentation: https://flowershow.app/

Recommendation: Quartz

Why Quartz

For publishing most of the vault with private exclusions, Quartz is the best fit:

FactorAssessment
Bulk publishing modelPublish all, exclude specific paths - matches use case
ULID supportpermalink: + title: frontmatter work well
CostFree (GitHub Pages, Netlify, or Vercel hosting)
Technical fitVault owner comfortable with Python/CLI; Node.js won’t be an issue
Framework exclusionignorePatterns cleanly excludes _framework/**
DataviewQuartz Syncer can compile queries to static content
Local previewTest full site before publishing
CustomizationFull control over templates and styling

Implementation Plan

Phase 1: Setup

  1. Install prerequisites

  2. Clone Quartz

  3. Configure exclusions in quartz.config.ts:

  4. Configure content source to point to vault

Phase 2: URL Strategy

Option A: Auto-generate from title (recommended)

  • Quartz uses title: frontmatter for URLs by default
  • “My Note Title” becomes /my-note-title
  • No additional frontmatter needed

Option B: Explicit permalinks

  • Add permalink: only where custom URL needed
  • Useful for frequently-shared links that must remain stable

Recommendation: Start with Option A, add explicit permalinks only for high-traffic pages.

Phase 4: Dataview Migration

Since Bases aren’t supported anywhere, consider:

  1. Identify Bases views that should appear on public site
  2. Convert to Dataview queries
  3. Install Quartz Syncer plugin to compile to static

Phase 5: Hosting

Recommended: GitHub Pages (free, simple)

Alternatives:

  • Netlify (free tier, automatic deploys)
  • Vercel (free tier, fast)
  • Cloudflare Pages (free, global CDN)

Phase 6: Custom Domain (Optional)

Configure DNS and update Quartz config for custom domain.

Future Considerations

Bases Support

Monitor these sources for Bases publishing support:

  • Obsidian Publish roadmap: https://help.obsidian.md/bases/roadmap
  • Obsidian Forum: https://forum.obsidian.md/t/do-bases-work-with-obsidian-publish/106703
  • Quartz GitHub issues

If Obsidian Publish adds Bases support before Quartz, re-evaluate recommendation.

Alternative: Dataview Publisher

If Dataview is sufficient (instead of Bases), the Dataview Publisher plugin renders queries to markdown for any platform.

Static Bases Rendering

A potential community solution could compile Bases views to static tables at build time, similar to how Quartz Syncer handles Dataview.
